## 2. 真实 Chrome 端到端（18/18）

环境坑：正式版 Chrome 144 会**静默忽略** `--load-extension`，`chrome://extensions`
里一条 unpacked 记录都没有；CDP 里看到的 `service_worker` 其实是 Chrome 内置组件
（Hangouts、Network Speech）。换成 **Chrome for Testing 145** 并带
`--enable-unsafe-extension-debugging` 后，扩展才真正加载
（`chrome-extension://hnemhgkpmfoaghcjdocclcamhdbibbnf/background.js`）。

验证链路：本地模拟站点（127.0.0.1:9911）提供 mp4 / pdf / png / js / `.m4s` /
`Content-Disposition` 附件的 1 KB 小文件 → 扩展 service worker 嗅探写入
`chrome.storage.session` → popup 渲染资源行与「本页检测到视频」卡片 →
点击「解析并下载本页视频」向桌面端送 `kind: media` → 点击 1 KB 下载链接触发
`chrome.downloads.onCreated` 自动接管并取消浏览器原生下载 → `tasks.json` 出现
对应任务且状态 `completed`。

实测 `tasks.json` 中 media 任务产物 2060 B（内置 yt-dlp 解析并合并成功），
`demo.txt` 自动接管任务 1000 B 完成。

## 3. 过程中发现并修复的两个真实缺陷

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 资源缓存并发覆盖 | 三个 `fetch` 同时返回时 `addResource` 的 `read → await → write` 互相覆盖整份列表，嗅探结果在 3 / 2 / 0 个之间随机跳 | 用 Promise 链 `enqueueResourceOp()` 串行化同一 tab 的读写 |
| `hidden` 被 CSS 覆盖 | `popup.css` 的 `.video-card{display:flex}` 优先级盖过 `[hidden]`，视频卡片和「全部发送」按钮永远显示 | 补 `[hidden]{display:none!important}` |

## 8. Windows 中文输出崩溃修复（PR #6）

**现象（用户实拍）**：Windows 上解析 B 站视频，任务 0 B 失败，错误为

```
yt-dlp 失败: ERROR: Unable to download video: [Errno 22] Invalid argument
Exception ignored while flushing sys.stdout: OSError: [Errno 22] Invalid argument
```

**根因链**：

1. PyInstaller 版 `yt-dlp.exe` 在 Windows 中文系统、stdout 被重定向到管道时，
   默认按系统 ANSI 代码页（GBK）编码输出；`--progress-template` 与
   `--print after_move` 里的中文标题 / 路径因此是非 UTF-8 字节。
2. 旧实现用 `BufReader::lines()` + `while let Ok(Some(line))`，遇到
   `InvalidData` 立即退出并 drop 掉 stdout 读端。Windows CRT 把向已关闭命名管道
   写入映射为 `EINVAL(22)`，yt-dlp 报进度时抛异常被包装成
   `Unable to download video`，退出时 flush 再抛一次。
3. Linux zipapp 版在 UTF-8 locale 下不触发，所以上一轮 18/18 端到端没暴露。

**修复**（`crates/download-engine/src/media.rs`）：

- `Command` 增加 `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8:replace` /
  `PYTHONUNBUFFERED=1`，从源头统一输出编码并保证进度实时。
- 新增 `spawn_line_reader`：`read_until(b'\n')` 读原始字节 +
  `from_utf8_lossy`，只在真 EOF / 真 IO 错误时关闭读端；stdout / stderr 共用。
- 顺带修掉同一场景下暴露的次级缺陷：FLUXDONE 路径经 lossy 解码变乱码后，
  旧 `find_output` 只按文件名前缀兜底，会把一次成功下载误判成
  「下载完成，但未找到输出的视频文件」。新增 `snapshot_files` /
  `find_new_output`，启动前拍目录快照，按「新增或 mtime 变新的非空文件」
  定位真实产物（排除 `.part` / `.ytdl` / `.tmp`），再退回原兜底。
