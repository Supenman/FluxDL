### 本轮（#11）具体做了什么

- **`page-probe.js`**：新增 `platformOf()` / `jsonCandidates()` / `collectWorkNodes()` / `parsePlatformMedia()` 等纯函数；在抖音 `aweme/detail`、快手 `INIT_STATE` / `graphql`、首屏 SSR `_ROUTER_DATA` / `RENDER_DATA` 中按字段语义取 `play_addr.url_list` / `mainMvUrls` 的**无水印正片**；不再只靠通用 URL 正则碰运气。fetch / XHR / 内联脚本三处接入 `media` 上报。
- **`probe-bridge.js`**：结构化条目走独立 `media` 通道，`sanitizeMedia()` 白名单只透传 `url/title/author/ratio/platform` 五个字段，带 URL 硬校验 + 去重 + 数量上限；旧消息形态不变。
- **`background.js`**：`mediaFileName()` 按「标题 - 作者 - 清晰度.mp4」命名；`primary` 优先级让主按钮选中结构化正片；`mergeResource()` 保留 `primary/title/author/ratio`。
- **`popup.js`**：列表显示「解析正片」、清晰度、作者、标题 tooltip。
- **边界**：不内嵌 WebView、不计算 `a_bogus` / `msToken`、不读取 `document.cookie`、不透传 `Authorization`；旧探针链路完全兼容。

### 顺带修掉的 3 个契约失败点

1. `isPlatformVideoUrl()` 里 `.mp4` 扩展名早退，导致带 `user:pass@` 的凭证 URL 绕过校验 → 把协议/凭证硬校验前置。
2. `sanitizeMedia()` 漏去重（旧 `sanitizeMessage()` 有 `!out.includes(u)`，新链路没加）→ 补上按 URL 去重、保留首条。
3. 两条 media 都被标 `primary: true`，`size` 都是 0，兜底 `rank()` 按 `.mp4` 扩展名排序，主按钮被 1080p 备用片顶掉 → 改为**只给首条无水印正片标 `primary`**。

## 七、已知风险 / 坑

1. **抖音 `a_bogus`**：纯 HTTP / SSR 已走不通，必须让页面 JS 跑完反爬挑战。当前 yt-dlp **不会生成** `a_bogus`，Cookie 不足以解析。`iesdouyin` 分享页只剩反爬壳（`byted_acrawler` / `__ac_signature`）。
2. **B 档契约会「假通过」**：`check_media_parse_contract.cjs` 仍按「抖音放行 + Cookie 通道」的旧假设断言，它 PASS **不代表功能可用**，只代表代码形状没被破坏。
3. **抖快直链无扩展名**：任何新增下载入口都必须显式 `kind:"http"`，否则会被 `looks_like_media()` 误判成 Media 任务再被拦，表现为「点了没反应」。
4. **交付包两层是独立拷贝**：`/workspace/fluxdl-dist/` 顶层与 `archive-0.3.9/` inode 不同，改一处必须同步另一处。
5. **`fluxdl.exe` 与扩展解耦**：本轮只改扩展 JS，exe 未重编；若后续改 Rust / 前端 TS，需按 `docs/版本管理.md` 第九节走 `cargo xwin build` + `vite build` + `repack.py`。
6. **本轮改动未真机验证**：契约与逐字节一致性只保证「打包进去的是新代码」，不保证抖音线上接口形态没变化；真机结果回来前别下「已修复」结论。
7. **主仓库位置**：`/workspace` 顶层只有 `fluxdl-dist` 和 `README.md`，**不是** git 仓库；源码在 `/root/work/winbuild/fluxdl`。
