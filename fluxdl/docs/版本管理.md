# FluxDL 更新与回退设计

> 目标：**装一次之后，以后每次发版只要在程序里点一次「更新」**，不需要重下安装包、
> 不需要重装、不需要管理员权限；装坏的版本能一键退回上一版，启动就崩的版本能自动退回。

## 1. 「增量」到底增量在哪

FluxDL 的体积构成决定了整包重下非常浪费：

| 组件 | 典型体积 | 变化频率 |
|---|---|---|
| `fluxdl.exe`（应用壳 + 嵌进去的前端资源） | 约 10 MB | 每次发版 |
| `tools/yt-dlp.exe` | 23 MB | 上游改版就变，接近每周 |
| `tools/ffmpeg.exe` | 78 MB | 季度级 |
| `browser-extension/` | < 200 KB | 偶发 |

所以不做二进制差分（bsdiff / zstd patch —— 要为每个历史版本准备 patch，杀软对"自己改自己"
也很敏感），而是做**组件级增量**：

- 应用更新只下载 Release 里的单文件 `fluxdl.exe`（约 10 MB），不下载 47 MB 的 `Setup.exe`；
- 工具更新由 `tools/` 独立管理，只下载变化的那一个工具，支持多版本共存；
- 浏览器扩展体积可忽略，随安装包走。

## 2. 版本号规则

`MAJOR.MINOR.PATCH[-prerelease]`：

| 位 | 什么时候 +1 | 例子 |
|---|---|---|
| MAJOR | 破坏性变更：配置/任务文件不兼容、必须手动迁移 | `1.0.0` |
| MINOR | 加功能，向后兼容 | `0.3.0 → 0.4.0` |
| PATCH | 只修 bug | `0.3.1` |
| `-beta.N` | 预发布，优先级低于同号正式版 | `0.4.0-beta.1 < 0.4.0` |

清单里的版本号是唯一事实来源：程序只比较版本号，不看时间戳（时钟误差会误判）。

## 3. 目录与状态

```
安装版
  %LOCALAPPDATA%\FluxDL\fluxdl.exe                         ← 唯一在跑的
  %LOCALAPPDATA%\com.fluxdl.desktop\app-versions\
      0.3.0\fluxdl.exe                                     ← 版本库
      0.2.0\fluxdl.exe
      app-version-state.json

便携版（解压目录）
  FluxDL\fluxdl.exe
  FluxDL\portable.flag                                     ← 有它就把版本库放本目录
  FluxDL\app-versions\0.3.0\fluxdl.exe
```

`app-version-state.json`：

| 字段 | 含义 |
|---|---|
| `active` | 当前**确认可用**的版本（只有启动成功才写） |
| `previous` | 上一版本，供一键回退与界面展示 |
| `pending` | 已下载、等待下次启动生效的版本 |
| `attempts` | `pending` 版本的连续启动失败次数 |
| `rolledBackFrom` | 上次自动回退"从哪个版本退下来"，用于防止两版来回弹跳 |

`update-state.json`（引擎维护）记录一次替换的现场：`target` / `staged` / `backup` /
`expectSha256` / `fromVersion` / `toVersion`，用于"换到一半进程挂了"的恢复。

## 4. 更新流程

```
① 检查更新   GET update-manifest.json → 比对 app.latest 与当前版本
② 点「更新」  只下载约 10 MB 的 fluxdl.exe → app-versions\<新版本>\fluxdl.exe.download
③ 校验       SHA-256 与清单不符 → 删除，绝不安装（fail-closed）
④ 登记       rename 成 app-versions\<新版本>\fluxdl.exe，pending = 新版本
⑤ 自动切换   校验通过后紧接着：复制到 <当前 exe>.new → 写 update-state.json → 生成 .cmd
⑥ 退出       程序 app.exit(0)，脚本接手（用户只点了那一次）
⑦ 替换       等旧文件可改名 → 备份 .bak → 覆盖 → 比对大小 → 拉起新进程
⑧ 自检       新进程启动时 attempts+1；UI 真正起来后 attempts=0、active=新版本
```

**第 ⑦ 步为什么不用固定延时**：Windows 锁住运行中的 exe，`move` 会失败。
早期实现是"睡 3 秒再换"，碰上关机慢、正在落盘任务列表就会失败。
现在改成**反复尝试改名**：改不动说明旧进程还在，改得动立刻换，最多等 60 秒；
换完还比对文件大小，copy 被磁盘满打断就立刻用 `.bak` 还原。

**第 ⑧ 步为什么需要**：没有常驻看护进程，只能靠"自己记录自己有没有起来"。
启动阶段就崩（缺 dll、配置损坏、setup panic）的进程永远走不到写成功标记那一步，
计数会留在磁盘上，供下次启动判定。

## 5. 回退

### 5.1 手动回退

设置 → 视频下载 → **主程序版本** → 选旧版本 → 「回退到此版本」→ 确认 → 自动重启。

和更新走**完全相同**的替换脚本，只是源文件从"新版本"换成"版本库里的旧版本"。
`previous` 会被设为刚离开的版本，所以随时能再切回来。

### 5.2 自动回退（启动即崩）

| 情况 | 判定 | 处理 |
|---|---|---|
| `pending` == 正在运行的版本 | 升级后首次启动 | `attempts += 1` |
| `attempts` 达到 2 | 连续两次起不来 | 用 `previous` 替换回去并重启 |
| `pending` != 正在运行的版本 | 替换脚本根本没跑（取消/断电/被拦截） | 清 `pending`，保留原版本，提示重试 |
| 没有 `previous`，或它就是上次被回退的版本 | 无可回退 / 会来回弹跳 | 放弃自动处理，提示下载完整安装包 |

**"起来过之后崩溃"不触发回滚**：那多半是任务本身的 bug，盲目退旧版只会掩盖问题。
只有"启动阶段失败"才算版本不可用。

## 6. 关键约束

1. **安装目录必须在用户可写区**。当前 `InstallDir = $LOCALAPPDATA\FluxDL` +
   `RequestExecutionLevel user`，所以自更新不需要 UAC。装到 `Program Files` 就必须
   每次弹提权，因此不支持这种装法。
2. **替换发生在进程退出之后**，所以点更新后窗口会先关掉、1~2 秒后自己重开。
   这是 Windows 文件锁的必然结果，不是崩溃。
3. **下载与生效解耦**：下载完不点更新不会动正在运行的文件；下次启动也不会自己切过去。
4. **SHA-256 缺失即拒绝**：清单没写哈希的更新一律不装。
5. **版本库会占空间**：默认保留 3 个（约 30 MB），可在设置页删到只剩 2 个。

## 7. 边界情况

| # | 场景 | 行为 |
|---|---|---|
| 1 | 脚本已生成，用户又手动开了一次程序 | 两进程争抢文件；脚本改名失败则保留原文件，状态由 `boot_guard` 按 `pending` 判定 |
| 2 | 替换后启动即崩 | 计 2 次后自动回退 |
| 3 | 回退后仍崩 | 停止尝试，提示下载完整安装包（不死循环） |
| 4 | 便携版放在只读目录 / U 盘 | 写入探测失败 → 明确提示"目录不可写"，不假装成功 |
| 5 | 磁盘空间不足 | 预检需 2×exe 空闲，不足直接拒绝并报出需要多少 |
| 6 | 有下载任务正在跑 | 弹窗让用户选「立即更新」或「完成当前任务后更新」 |
| 7 | 更新包哈希不符 | 删除暂存文件，横幅提示"校验失败，已取消" |
| 8 | 版本库残留破损目录（exe 被删） | 扫描时过滤，不展示；`prune` 顺手清掉 |
| 9 | 想装比当前更旧的版本 | 检查更新不会提示降级；只能从版本下拉手动回退 |
| 10 | 覆盖安装新版本 | 安装器先把旧 exe 收进版本库，保证仍有回退位 |
| 11 | 卸载 | 清理安装目录 + 版本库 + 工具副本 |
| 12 | `tasks.json` 结构变更 | 读取按 `schema` 迁移，旧字段缺省不报错 |

## 8. 涉及文件

| 文件 | 职责 |
|---|---|
| `crates/download-engine/src/update.rs` | 版本号比较、清单解析、SHA-256、替换脚本、启动恢复 |
| `src-tauri/src/appversion.rs` | 版本库扫描、更新登记、自替换、`boot_guard`、回退、清理 |
| `src-tauri/src/version.rs` | 检查更新、下载、更新历史、启动提示 |
| `src-tauri/src/tools.rs` | yt-dlp / ffmpeg 多版本管理（同一套思路） |
| `src/components/UpdateSection.tsx` | 版本面板、主程序版本下拉、更新横幅 |
| `tools/build-update-manifest.py` | 生成 `update-manifest.json`（体积 + 哈希 + 历史） |
| `package.nsi` / `repack.py` | 安装版与便携版布局 |

## 9. 发版清单（开发端）

1. 改代码 → `cargo test --workspace` 与 `src-tauri` 下 `cargo test --lib` 全绿；
2. `npx vite build` → `cargo xwin build --release --target x86_64-pc-windows-msvc`；
3. `python3 repack.py` 出安装包 / 便携包 / 单文件 exe；
4. `python3 tools/build-update-manifest.py --version X.Y.Z --exe ... --notes ...`；
5. 把 `fluxdl.exe` 与 `update-manifest.json` 一起传 Release（程序默认从
   `releases/latest/download/update-manifest.json` 取清单）。
