## 一、结论先行

任意网页的 JS 可以**静默把任意文件下载到用户目录**。根因不是"CORS 配得太松"，而是**服务端没有任何请求准入判断**。修复后已用真实 HTTP 报文验证：网页来源全部 403 且拿不到 CORS 许可，扩展来源正常放行。

**端口 35917、令牌 `fluxdl-local-v1`、扩展代码一律未改动**，遵守项目约定。

## 二、漏洞机理

原实现（`lib.rs`）：

```rust
const CAPTURE_TOKEN: &str = "fluxdl-local-v1";           // 写在扩展源码里，是公开值
...
"Access-Control-Allow-Origin: *\r\n"                     // 所有响应都带通配符
```

攻击只需一个网页：

```js
fetch("http://127.0.0.1:35917/api/downloads", {
  method: "POST",
  headers: { "content-type": "text/plain", "x-fluxdl-token": "fluxdl-local-v1" },
  body: JSON.stringify({ url: "https://..." }),
});
```

### 为什么"只把 `*` 改掉"挡不住

| 攻击方式 | 原实现为何放行 |
|---|---|
| **简单请求**（`Content-Type: text/plain`） | 不触发预检，直接带上令牌头；服务端不检查 Content-Type，`serde_json::from_slice` 照样解析 |
| **带自定义头的请求** | 触发 OPTIONS 预检，但原实现**无条件**返回 `204 + ACAO:* + Allow-Headers: x-fluxdl-token`，等于给网页发通行证 |
| **DNS rebinding** | 把域名解析到 127.0.0.1 后请求变成"同源"，Origin 可能缺失或为网页域名，Host 却是攻击者域名 |

> 关键判断：**令牌不是秘密**。它硬编码在扩展的 `background.js` 里，任何装了扩展的人（或看过源码的人）都知道。单靠它做鉴权等于没做。

## 三、修复设计

新增 `src-tauri/src/capture_guard.rs`，把准入逻辑抽成**不依赖 Tauri / WebView 的纯模块**，这样才能在 Linux 容器里单独编译验证。

| 检查 | 规则 | 挡住什么 |
|---|---|---|
| **Host 白名单** | 只认 `127.0.0.1` / `localhost` + 端口 `35917`（或省略端口） | DNS rebinding：请求以"同源"形式打进来时 Origin 可能缺失，但 Host 一定不是回环地址 |
| **Origin 白名单** | 放行 `chrome-extension://` / `moz-extension://` 与**无 Origin**；拒绝 `http(s)://`、`null`、`file://` 等 | 任意网页。浏览器跨域请求必定带 Origin，且 Origin 是 JS 无法设置的 forbidden header |
| **CORS 回显** | 只在扩展来源时回显**具体** Origin + `Vary: Origin`，不再返回 `*` | 网页预检拿不到允许头，浏览器直接拒绝后续请求 |
| **准入前置** | `handle_capture_conn` 在任何处理之前（含 OPTIONS 预检、`/api/health`）先过检查，拒绝返回 403 且**不带任何 ACAO 头** | 预检绕过 |

### 为什么"无 Origin"仍放行

扩展 service worker 是否发送 `Origin` 头在不同 Chrome 版本/请求方式下不一致。放行可避免误伤正常功能；而网页想走这条路就得用**简单请求**，带不上 `x-fluxdl-token` 自定义头，令牌校验仍会挡住。

设计上不依赖"扩展一定带某个 Origin"这个假设——**带扩展 Origin** 和 **不带 Origin** 两条路径都已放行且实测通过，所以无论浏览器实际行为如何，功能都不会坏。

### 改动文件

| 文件 | 改动 |
|---|---|
| `src-tauri/src/capture_guard.rs` | 新增：`check` / `is_allowed_host` / `is_allowed_origin` / `extension_origin` / `build_response` + 7 个单测 |

## 五、已知残余与后续

1. **固定令牌仍是公开值**：本机任意进程（`curl`）知道它就能添加任务。这属于本机权限范围，威胁等级远低于"任意网页"。彻底解决需改成运行时随机令牌 + 扩展配对，会改动写死在扩展里的常量，需要单独评估。
2. **`add()` 目标地址**：此前报告称其为"SSRF 跳板"，复查 `manager.rs` 已限制 scheme 为 `http`/`https`，且响应只落本地文件、攻击者读不到内容，实际风险主要是内网探测。**该判断已下调**，优先级低于本 PR 所修问题。
3. **需你本地确认一次**：加载扩展后右键「用 FluxDL 下载此链接」，应正常添加任务。容器里没有 Windows + Chrome 环境，扩展联调无法实跑。
